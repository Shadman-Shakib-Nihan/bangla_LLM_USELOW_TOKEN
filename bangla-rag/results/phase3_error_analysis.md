## Caveats

- The 100k MIRACL slice is easier than the full 297k-passage corpus: it mixes judged passages with a random sample and was built for this phase, so absolute scores should not be read as full-corpus estimates.
- TyDi is scored two ways: strict gold passage ID and answer-string hit. The answer-string rule is more lenient and checks all chunks of the retrieved top-k parents.
- Validation sets are small: MIRACL dev n=411, TyDi validation n=113. Subgroups are much smaller (TyDi validation over-length gold n=4), so their CIs and example counts are unstable.
- The Phase 2 `is_short` flag (stripped characters <20) matches no gold passage in either reporting set; the short-gold sensitivity table therefore also uses e5-token thresholds.
- RRF hyperparameters (k=5, w_BM25=0.5) were tuned on MIRACL train only, not on dev or TyDi validation.
- MRR for BM25/dense is over the full parent ranking; hybrid MRR is over the fused top-100+top-100 candidate list. This depth difference matters only for a handful of queries but should be kept in mind.
- Paired bootstrap resamples queries, not passages; it measures uncertainty over this query sample, not over the corpus.
- No BGE-M3, compression, or external API call was run for this analysis.
